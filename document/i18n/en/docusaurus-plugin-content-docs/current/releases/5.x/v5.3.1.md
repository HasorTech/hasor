# v5.3.1 (In Development)

## Changes

1. `RenderEngine` supports a default response content type. Built-in JSON and text engines use `application/json` and `text/plain`, while explicit response types retain precedence.
2. `@Bean` in `hasor-config` supports concrete classes, registering business Beans from scan packages without individual `bindType` calls. See [Java annotation configuration](../../guides/core/conf/java-config.md).
3. Add `AnnotationInjector` and `ApiBinder.bindAnnotationInjector(...)` for custom annotation field injection before Bean initialization. See [Custom annotation injection](../../guides/core/ioc/by_annotation.md).
4. When `sources` are provided without an explicit scan range, Boot scans their packages and subpackages. Explicit configuration takes precedence; an empty range disables scanning. See [Boot launcher](../../guides/deployment/boot-launcher.md).
5. Correct configuration loading order so application configuration supplied through `META-INF/hasor.schemas` can override framework defaults.
6. Fix package scanning that also matched neighboring packages with the same name prefix.
7. Run matching business filters before continuing the Servlet filter chain when neither an Action nor a static resource matches.
8. Fix result rendering and failure dispatch for framework-managed asynchronous calls, avoiding repeated Action execution during error dispatch and preserving the request context path on worker threads.
9. When the application starts Servlet asynchronous processing, it owns the response. Defer MVC interceptor `afterCompletion` until the asynchronous request ends, including error or timeout information.
10. Skip automatic return-value rendering when an Action accepts a `ServletResponse` parameter and returns `null`, preserving the application's response.
11. Add `hasor.boot.web.enabled` for headless operation while retaining Web dependencies. Both unified Boot and ordinary Hasor startup can disable the embedded container. See [Headless mode](../../guides/deployment/boot-launcher.md#headless-mode).

## Upgrade notes

- Custom `RenderEngine` implementations must add `defaultContentType()`. Return `null` when no default type is declared.
- Custom `ApiBinder` implementations must add `bindAnnotationInjector(...)`. `BasicBinder` and `ApiBinderWrap` already implement it.
- When `sources` are provided, Boot now defaults to scanning their packages. Set `hasor.loadPackages` explicitly to keep a fixed scan range, or set it to an empty string to disable scanning.
