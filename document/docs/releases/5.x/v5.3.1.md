# v5.3.1（开发中）

## 更新内容

1. `RenderEngine` 支持默认响应类型，内置 JSON、文本引擎分别使用 `application/json`、`text/plain`，保留显式响应类型的优先级。
2. `hasor-config` 的 `@Bean` 支持标注具体类，按扫描包注册业务 Bean，无需逐个调用 `bindType`。详见 [Java 注解配置](../../guides/core/conf/java-config.md)。
3. 新增 `AnnotationInjector` 和 `ApiBinder.bindAnnotationInjector(...)`，在 Bean 初始化前完成自定义注解字段注入。详见 [自定义注解注入](../../guides/core/ioc/by_annotation.md)。
4. Boot 指定 `sources` 且未显式配置扫描范围时，扫描这些启动源所在包及子包；显式配置优先，空范围关闭扫描。详见 [Boot 启动器](../../guides/deployment/boot-launcher.md)。
5. 修正配置加载顺序，应用通过 `META-INF/hasor.schemas` 提供的配置可以覆盖框架内置默认值。
6. 修复包扫描误匹配同名前缀的相邻包的问题。
7. 修复未匹配 Action 和静态资源时跳过业务过滤器的问题，继续 Servlet 过滤链前先执行匹配的业务过滤器。
8. 修复框架异步调用的结果渲染与失败分发，避免异常分发时重复执行 Action，并保留工作线程中的请求上下文路径。
9. 应用自行启动 Servlet 异步处理时，由应用负责响应；MVC 拦截器的 `afterCompletion` 延后至异步请求结束，接收错误或超时信息。
10. Action 接收 `ServletResponse` 参数且返回 `null` 时，不再自动渲染返回值，保留应用写入的响应。
11. 新增 `hasor.boot.web.enabled` 开关，支持保留 Web 依赖的无头运行；统一 Boot 和普通 Hasor 启动均可关闭内嵌容器。详见 [无头运行](../../guides/deployment/boot-launcher.md#无头运行)。

## 升级说明

- 自定义 `RenderEngine` 实现需增加 `defaultContentType()`；不声明默认类型时返回 `null`。
- 自定义 `ApiBinder` 实现需增加 `bindAnnotationInjector(...)`；继承 `BasicBinder` 或使用 `ApiBinderWrap` 时已有实现。
- Boot 传入 `sources` 时，默认扫描范围改为启动源所在包。需要固定范围时显式设置 `hasor.loadPackages`；设置为空字符串可关闭扫描。
