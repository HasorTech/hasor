# v5.4.0 (2026-11-27)

```xml
<dependency>
    <groupId>net.hasor</groupId>
    <artifactId>hasor-web</artifactId>
    <version>5.4.0</version>
</dependency>
```

## 更新内容

- 新增
  - `hasor-config` 支持扫描标注 `@Bean` 的具体类并注册为 Bean。详见[Java 注解配置](../../guides/core/conf/java-config.md)。
  - 新增 `AnnotationInjector` 和 `ApiBinder.bindAnnotationInjector(...)`，支持在 Bean 初始化前按自定义注解注入字段。详见[自定义注解注入](../../guides/core/ioc/by_annotation.md)。
  - 新增 `WebApiBinder.addClasspathResource(...)`，将应用类路径中的目录映射到静态资源 URL。
  - 新增 `hasor.boot.web.enabled`，支持在保留 Web 依赖的情况下关闭内嵌容器，适用于 Boot 和普通 Hasor 启动。详见[无头运行](../../guides/deployment/boot-launcher.md#无头运行)。
- 修复
  - 修复配置加载顺序，使应用通过 `META-INF/hasor.schemas` 提供的配置可以覆盖框架默认值。
  - 修复包扫描误匹配同名前缀的相邻包的问题。
  - 未匹配 Action 或静态资源时，先执行匹配的业务过滤器，再继续 Servlet 过滤链。
  - 修复框架异步调用的结果渲染与异常分发，避免重复执行 Action，并保留工作线程中的请求上下文路径。
  - 应用自行启动 Servlet 异步处理时，由应用负责响应，MVC 拦截器的 `afterCompletion` 在异步请求结束时执行，并接收异常或超时信息。
  - Action 接收 `ServletResponse` 参数并返回 `null` 时，跳过自动渲染，保留应用写入的响应。
- 优化
  - `RenderEngine` 支持声明默认响应类型。内置 JSON 和文本引擎分别使用 `application/json` 和 `text/plain`，显式设置优先。
  - Boot 指定 `sources` 时，默认扫描启动源所在包及其子包，显式配置优先。
  - Cobble 升级至 `5.0.5`。
  - 项目测试迁移至 JUnit Jupiter，并通过 JaCoCo 生成覆盖率报告。
  - 更新 Hasor 首页、站点导航和 Boot 示例。

## 升级说明

- 自定义 `RenderEngine` 实现需实现 `defaultContentType()`。无需声明默认类型时返回 `null`。
- 自定义 `ApiBinder` 实现需实现 `bindAnnotationInjector(...)`。`BasicBinder` 和 `ApiBinderWrap` 已提供实现。
- Boot 传入 `sources` 的应用如需保留原有扫描范围，需显式设置 `hasor.loadPackages`。设置为空字符串可关闭扫描。详见[Boot 启动器](../../guides/deployment/boot-launcher.md)。
